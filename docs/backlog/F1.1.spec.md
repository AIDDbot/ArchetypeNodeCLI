# F1.1 Initialize package and TypeScript config Specification

Bootstrap the repository with a minimal, TypeScript-first Node v24 CLI skeleton: create package.json, tsconfig.json, a base src/ folder, and minimal npm scripts to enable type checking and future expansion.

- Epic: E1 Project Bootstrap
- Priority: ‼️ Critical
- Product Requirements:
  - R1 Core CLI framework and help (foundation for later CLI work)
  - Technical Constraints: Node v24, TypeScript, minimal dependencies

## User Story 1

- As a CLI developer
- I want to have a clean Node + TypeScript project initialized
- So that I can start implementing commands without setup friction

### Acceptance Criteria

- [ ] The repository SHALL contain package.json declaring name, version, type=module, engines (Node >=24), and minimal scripts (e.g., "typecheck", "clean").
- [ ] WHEN running `npm install` on Node v24, THEN dependencies install without errors, WHERE the project has no unnecessary runtime deps at this stage.
- [ ] IF I open the project in an editor, THEN TypeScript config is recognized (strict mode on), WHILE targeting modern Node ESM.

## User Story 2

- As a CLI developer
- I want a base TypeScript configuration
- So that I get strict type safety aligned with Node v24 ESM

### Acceptance Criteria

- [ ] A tsconfig.json SHALL exist with strict=true, noEmit for dev type checking, module set for Node ESM, and reasonable lib targets.
- [ ] WHEN running the script `npm run typecheck`, THEN TypeScript finishes with no errors on the empty scaffold.

## User Story 3

- As a CLI developer
- I want a conventional folder structure
- So that code organization is clear from the start

### Acceptance Criteria

- [ ] A src/ folder SHALL exist with a placeholder entry file (e.g., src/index.ts) reserved for future CLI wiring.
- [ ] WHERE future features will add CLI entrypoint and commands; THEN no executable CLI behavior is required in this feature.

> End of Feature Specification for F1.1, last updated 2025-08-19.
