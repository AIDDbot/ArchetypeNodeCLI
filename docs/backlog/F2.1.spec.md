# F2.1 `--env-file` wiring and config access Specification

Enable environment configuration using Node’s built-in `--env-file` flag and expose a minimal, typed accessor for reading env variables within commands. Avoid `dotenv` and keep defaults in code. Support optional env files for smoother DX.

- **Epic**: E2 Configuration & Environment
- **Priority**: ‼️ Critical
- **Product Requirements**: 
  
- R2 Environment configuration

## User Story 1

- **As a** CLI user
- **I want to** load environment variables from a `.env` file using Node’s `--env-file`
- **So that** I can configure the CLI without hardcoding secrets or values

### Acceptance Criteria

- [ ] SHALL allow running the CLI with `--env-file=.env` such that variables are available via `process.env`.
- [ ] WHEN the specified env file does not exist AND `--env-file-if-exists` is used, THEN the CLI SHALL still start without error.
- [ ] IF the same variable is defined in both the file and the environment, THEN `process.env` value SHALL take precedence.

## User Story 2

- **As a** CLI developer
- **I want to** read environment variables through a small typed accessor
- **So that** commands can safely access configuration with defaults

### Acceptance Criteria

- [ ] SHALL provide a `getConfig()` function exposing typed accessors (e.g., getString, getNumber, getBoolean) with defaults.
- [ ] WHEN a required variable is missing, THEN `getConfig()` SHALL return a clear error or default according to the call site choice.
- [ ] SHALL avoid adding `dotenv`; rely on Node `--env-file`.

> End of Feature Specification for F2.1, last updated 2025-08-19.
